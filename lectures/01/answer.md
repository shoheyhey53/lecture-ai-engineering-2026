# 第1回 解答

## 演習

- 講座に固有の質問へのモデルの回答：講座の具体的な内容は分からないと前置きし、プロンプト技術、AIの理解度、宿題の難易度という3通りの可能性を挙げた。
- 用語集との比較：正しくは「基礎・実装・発展」から1つに取り組めば完了。回答は一般的な推測を含み、「必須・基礎」など講座の実際と異なる説明もあった。講座固有の情報を持たないモデルの回答は、根拠を確かめる必要がある。
- 表示できたトークン数（入力 / 出力）：21 / 648（gemini-3.5-flash-lite、この質問の実行結果）。

## 宿題

- 取り組んだレベル：基礎
- やったこと：「LoRAとは何ですか？」を gemini-3.5-flash-lite と gemini-3.1-flash-lite に、それぞれ同じ設定で3回ずつ質問した。回答全文は results.txt に記録した。
- 結果：6回とも LoRA を Low-Rank Adaptation とし、元のモデルを固定して追加部分を学習する効率的な手法として説明した。出力トークン数は 3.5 が 585・606・466、3.1 が 691・789・705。今回の3.1の回答は3つとも3.5より長かった。3.5では「小さな脳」「付箋」「メモ帳」など例えが変わり、3.1では辞書と付箋の例えが複数回現れた。
- 気づき・疑問：同じ質問・同じモデルでも長さや例えは変わる。モデルの違いを一般化するには3回ずつでは不十分。回答にはデータ量が必ず少なく済むような説明や、モデル全体を動かす必要がないという不正確な説明もあったため、流暢さだけで正しさを判断せず確認したい。LoRAは通常、ベースモデルの重みを固定して低ランク行列を学習するが、ベースモデル自体の計算は必要になる。

### 実装：会話履歴を保つ

- `uv run python -m app.ask --chat` で、ひとつの Gemini Chat セッションを使って連続した質問を送れるようにした。空行は送らず、`/quit`・`/exit`・EOF で終了する。従来の単発質問も利用できる。SDK のチャットセッションが履歴を保持するため、次の呼び出しには過去のやり取りが含まれる。
- 実際の動作確認：最初に「架空のペンギンの名前はミントです。覚えてください。」と伝え、続けて「その名前を一言で答えてください。」と尋ねると、「ミント」と返った。2ターン目の入力は63トークンで、1ターン目の16トークンより増えた。入力文と応答は `chat_demo.txt` および本説明に記録した（標準入力のパイプ実行では質問文自体は画面にエコーされない）。
- 検証：会話セッションが1つだけ作られること、空行を無視して2回送信すること、EOFで終了することをテストした。実 API での会話は Codex が操作した。

### 発展：応答時間とトークン数

2モデルに「LoRAとは何ですか？」「AIE2026の講座の宿題にある3レベルとは何ですか？」をそれぞれ100字以内の指示付きで3回ずつ送った。`perf_counter` で API 呼び出しの前後を測定し、ネットワークや応答待ちを含む。各呼び出しの間には10秒待った。値は `benchmark_results.json`、計測コードは `scripts/compare_models.py` に保存した。生成設定は API の既定値。

| モデル | 質問 | 所要時間（秒・各3回） | 平均（秒） | 入力トークン | 出力トークン（各3回） |
|---|---|---|---:|---:|---|
| gemini-3.5-flash-lite | LoRA | 3.695 / 0.965 / 2.511 | 2.390 | 17 | 61 / 59 / 56 |
| gemini-3.5-flash-lite | 宿題の3レベル | 3.684 / 4.277 / 1.114 | 3.025 | 30 | 62 / 65 / 66 |
| gemini-3.1-flash-lite | LoRA | 1.177 / 0.889 / 1.059 | 1.042 | 17 | 52 / 52 / 56 |
| gemini-3.1-flash-lite | 宿題の3レベル | 0.866 / 1.037 / 0.743 | 0.882 | 30 | 69 / 76 / 66 |

この実行では3.1の方が速かったが、各3回の順次計測であり、混雑・ネットワーク・生成内容にも左右されるため、常に速いとは結論できない。3レベルの回答では講座固有の内容を知らず、レベル1〜3の一般的な説明を返す例があり、流暢さや速さだけでは正確さを判断できない。出力トークンは `candidates_token_count`、入力は `prompt_token_count` で、思考トークンは今回メタデータに値がなかった。

12回の測定はいずれも成功し、429は観測されなかった。10秒の待機で今回成功したことは、常に制限に達しない保証ではない。Google の [レート制限の説明](https://ai.google.dev/gemini-api/docs/rate-limits) によれば、制限はモデルや利用枠により異なり、1分あたりのリクエスト数・入力トークン数、1日あたりのリクエスト数などで適用され、APIキー単位ではなくプロジェクト単位で管理される。長い会話は入力トークンを増やすため、リクエスト数だけでなくトークン制限にも注意する。

基礎・実装・発展の3つに取り組んだため、最高レベルは「発展」。
